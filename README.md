# دعوتي — منصة دعوات المناسبات عبر واتساب

تطبيق ويب عربي (RTL) يعمل من متصفح الجوال: أنشئ مناسبة ← أضف المدعوين ← أرسل الدعوات من **واتسابك أنت** ← استقبل الردود ← تابع الإحصائيات.
اسم المنتج وألوانه في مكان واحد: `src/config/brand.ts` و`src/app/globals.css`.

## التقنيات

| الجزء | المستخدم |
|---|---|
| الواجهة والخادم | Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 |
| البيانات والدخول | Supabase: Auth (رمز/رابط بالبريد)، PostgreSQL مع RLS، Storage، Realtime |
| التحقق | Zod + React Hook Form |
| الأرقام | libphonenumber-js (الافتراضي السعودية، مع دعم بقية الدول) |
| الاستيراد/التصدير | papaparse (CSV)، read-excel-file / write-excel-file (xlsx)، محلل vCard داخلي |
| الاختبارات | Vitest + PGlite (Postgres حقيقي داخل العملية لاختبار الـRLS والدوال) |
| النشر | Vercel |

## التشغيل المحلي

```bash
npm install
cp .env.example .env.local     # ثم عبّئ القيم (انظر أدناه)
npm run dev                     # http://localhost:3000
npm run check                   # lint + typecheck + الاختبارات
```

## متغيرات البيئة

| المتغير | إلزامي | الوصف |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | نعم | رابط مشروع Supabase |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | نعم | المفتاح العام (publishable أو anon). آمن في المتصفح لأن RLS تحمي البيانات |
| `INVITE_TOKEN_SECRET` | نعم | سر الخادم لتوقيع روابط المدعوين (32 حرفًا أو أكثر). **تغييره يُبطل كل روابط الدعوات القائمة** |
| `NEXT_PUBLIC_SITE_URL` | يُنصح به | الرابط العام للموقع، يُستخدم في روابط الدعوات |
| `SUPABASE_SERVICE_ROLE_KEY` | اختياري | يفعّل «حذف حسابي» فقط. يبقى في الخادم ولا يصل للمتصفح |
| `NEXT_PUBLIC_BRAND_NAME` / `NEXT_PUBLIC_SUPPORT_EMAIL` | اختياري | الهوية |

توليد السر: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`

## إعداد Supabase (مرة واحدة)

1. أنشئ مشروعًا في Supabase.
2. **قاعدة البيانات:** نفّذ ملفات `supabase/migrations/` بالترتيب، إما عبر `npx supabase link` ثم `npx supabase db push`، أو بلصق كل ملف في SQL Editor.
3. **Authentication → URL Configuration:** ضع Site URL = رابط موقعك، وأضف `https://YOUR-DOMAIN/auth/callback` (و`http://localhost:3000/auth/callback` للتطوير) إلى Redirect URLs.
4. **Authentication → Email Templates → Magic Link:** أضف الرمز ليتمكن مستخدمو iPhone من الدخول بالرمز بدل فتح الرابط داخل تطبيق البريد:
   ```html
   <h2>رمز الدخول</h2>
   <p style="font-size:28px;letter-spacing:6px"><b>{{ .Token }}</b></p>
   <p>أو اضغط: <a href="{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=email&next=/events">دخول</a></p>
   ```
5. لإرسال بريد بكميات حقيقية اربط SMTP خاصًا في Supabase (الخدمة المدمجة محدودة جدًا).

## النشر على Vercel

1. ارفع المستودع إلى GitHub واستورده في Vercel (الإعدادات الافتراضية لـNext.js).
2. أضف متغيرات البيئة أعلاه في Vercel (Production وPreview).
3. بعد النشر حدّث Site URL وRedirect URLs في Supabase إلى رابط Vercel.

## إضافة مدير للمنصة

لا يمكن لأي مستخدم أن يعيّن نفسه مديرًا، فالجدول لا يقبل الكتابة من التطبيق. من SQL Editor:

```sql
insert into public.platform_admins (user_id)
select id from auth.users where email = 'admin@example.com';
```

تظهر بعدها «إدارة المنصة» في القائمة: الإحصائيات، تعديل حدود الخطط، تغيير خطة مساحة عمل أو إيقافها.

## الخطط والحدود

الخطط في جدول `plans`: مجاني / احترافي / جهات. الحدود (المناسبات النشطة، المدعوون لكل مناسبة، أعضاء الفريق) تُطبَّق **داخل قاعدة البيانات** (triggers ودوال RPC) ولا يمكن تجاوزها من الواجهة. لا يوجد تحصيل مالي؛ نقطة الإضافة لاحقًا موصوفة في `src/lib/billing/provider.ts`.

## حدود وضع واتساب الشخصي (المرحلة الحالية)

- زر «فتح واتساب» يفتح رابط `wa.me` برقم المدعو ونص جاهز في واتساب المفتوح على جهاز المستخدم. **المستخدم هو من يضغط إرسال.** لا يوجد QR ولا وصول لجلسة واتساب.
- الحالات المعروضة صادقة: «لم تُرسل» ← «فُتح واتساب» (ضُغط الزر) ← «أُرسلت» (أكدها المنظّم بنفسه). لا توجد حالات «وصلت» أو «قُرئت» لأننا لا نملك هذه المعلومة.
- ردود المدعو داخل محادثة واتساب **لا يمكن قراءتها** من موقع ويب؛ يحدّثها المنظّم يدويًا ويُسجَّل أن التعديل يدوي ومن قام به ومتى (`rsvp_audit`).
- لا يمكن إرفاق صورة البطاقة تلقائيًا عبر `wa.me`؛ تظهر الصورة في صفحة الدعوة.
- «إرسال متتابع» يعرض مدعوًا واحدًا كل مرة، ولا يفتح نوافذ متعددة.
- Contact Picker يظهر فقط حيث يدعمه المتصفح (Chrome على أندرويد). في iPhone تظهر بدائل: ملف vcf، لصق قائمة، إدخال يدوي.

## التكامل الرسمي مستقبلًا (WhatsApp Business Platform / Cloud API)

الواجهة مجهّزة في `src/lib/messaging/provider.ts`. التفعيل يتطلب: حساب WhatsApp Business موثّقًا لكل جهة، قوالب رسائل معتمدة من Meta، موافقة المستلمين، توضيح الرسوم، ومسار Webhook موقّعًا يحدّث حالات التسليم والردود. لن تُضاف أدوات غير رسمية لمحاكاة واتساب ويب أو الإرسال الجماعي من رقم شخصي.

## الأمان باختصار

- RLS على كل الجداول، والصلاحيات (مالك/منظّم/مشاهد ونطاق مناسبات لكل عضو) تُحسب في قاعدة البيانات.
- إضافة المدعوين وتعديل حالاتهم تمر فقط عبر دوال `SECURITY DEFINER` تعيد التحقق من الصلاحية وتكتب سجل التدقيق.
- أرقام الجوال وتجزئات الروابط **غير قابلة للقراءة** بـSELECT عادي (صلاحيات أعمدة)؛ المشاهد لا يرى الأرقام أبدًا.
- رابط المدعو = HMAC-SHA256 بسرّ الخادم (256 بت)، ولا يُخزَّن إلا sha256 له. يمكن تدوير رابط أي مدعو.
- صفحة الدعوة لا تكشف أرقامًا أو بقية الضيوف، ولا تُفهرس (`noindex`)، ولا ترسل Referer.
- حدّ للطلبات على الرد العام (لكل رابط ولكل IP مُجزّأ)، وحماية تصدير CSV/Excel من حقن الصيغ، وحدود حجم وعدد سجلات للاستيراد.

## الاختبارات

`npm test` يشغّل:
- `tests/unit` — الأرقام السعودية بكل الصيغ، القوالب، روابط واتساب، الخرائط، الاستيراد (لصق/CSV/vCard)، التصدير، المناطق الزمنية، الرموز.
- `tests/db/rls.test.ts` — فصل المساحات، منع الكتابة بمعرّفات مزوّرة، إخفاء الأرقام، الأدوار والنطاق، حدود الخطط، الرد العام وحدوده.
- `tests/db/acceptance.test.ts` — سيناريوهات القبول من المواصفات من طرف لطرف (TypeScript + SQL الحقيقي).
